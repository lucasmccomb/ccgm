◑ Durable memory

How CCGM remembers what it learns

A cross-session memory that surfaces what you've learned at the start of every session — and a nightly job that mines your own transcripts to grow it, behind a human gate.

Read path self-improving · local · free · always on
Write path dreaming · nightly · opt-in · human-gated

The shape of it

Two halves, one store

The memory system splits cleanly into a read path that never leaves your machine and does the valuable work, and an optional write path that automates capture. The read path is complete on its own — you never need the write path to benefit from memory.

Read path

Stores learnings and surfaces the top-ranked ones at each fresh session start.

  • Module self-improving
  • Storage ~/.claude/learnings/ — a local git repo of append-only JSONL
  • Cost Free. No network calls.
  • Trigger SessionStart hook injects; /reflect & the CLI capture
Write path

A nightly analyzer mines your session transcripts and proposes new learnings for you to accept.

  • Module dreaming
  • Storage ~/.claude/dreaming/ — proposals, digests, scorecards
  • Cost Opt-in. Spends Anthropic API tokens (analyzer only).
  • Trigger Nightly launchd job → review via /dream-apply

The loop

How a memory travels

The read path is a four-step cycle: capture once, and it resurfaces itself at the right moment ever after. Reuse feeds back and strengthens it.

01 · CAPTURE
Log a learning
/reflect, /consolidate or the CLI write a pattern, pitfall, preference, or fact.
02 · STORE
Rank & decay
Lands in append-only JSONL, scored by confidence with time-decay and staleness.
03 · INJECT
Surface at start
The next fresh session gets the project's top-ranked learnings, token-budgeted.
04 · REUSE
Reinforce
When a learning pays off again, a verify raises its confidence and freshness.

Injection is frozen into the session's prompt prefix at start — so a memory is picked up by the next fresh session, not the one that logged it.

01 · MINE
Read transcripts
A deterministic Python miner extracts friction, corrections & PR links — no LLM yet.
02 · ANALYZE
Map → reduce
One API call per project + one across all of them turns evidence into candidate deltas.
03 · PROPOSE
Pending deltas
Each proposal is a per-change delta, written pending, tagged with its evidence.
04 · APPLY
Human accepts
You review the digest and /dream-apply — the default path from proposal to store.

Accepted proposals become ordinary learnings and feed the same read path above.

What gets remembered

Six kinds of learning

Every entry is one idea, actionably phrased, ideally anchored to real files so staleness detection can flag drift.

pattern
An approach that worked and should be reused.
pitfall
A known trap to avoid next time.
preference
A taste call — how you like things done.
architecture
A durable fact about how the codebase fits together.
tool
A tool or framework gotcha.
operational
An ops fact — deploys, CLIs, infra timing.

⚖︎  “Only log human-validated decisions” — the honest version

The store legitimately holds observed patterns, not just decisions a human explicitly ratified. But the integrity property you actually care about is real and enforced two ways: every memory is grounded in real, on-disk session evidence (nothing is invented), and every model-proposed memory passes a human gate before it is stored. Manual capture via /reflect is human-confirmed; automated capture via dreaming is human-accepted. A model never writes to the store on its own.

The background job

What “dreaming” does at night

Once a day a launchd LaunchAgent runs a chain — analyze → eval-refresh → optimistic-integrate → digest → reconcile → retention. Each step is exit-tolerant, so one failure never kills the rest of the chain. (Digest runs after integrate, so tonight's just-integrated batch is reported while its dwell window is still ahead of it.)

🔎

Deterministic mining, no model

Pure-Python transcript_miner reads the JSONL every session already writes and pulls out friction events (tool/hook errors), user-correction sequences, PR links, and token economics. A schema canary fails loud if Claude Code's transcript format drifts, rather than silently mining nothing.

🧠

Map → reduce over a direct API call

The evidence bundle goes to the Anthropic Messages API over curl — no nested agent runtime, which removes the exec-escape attack surface. One map call per project, one reduce call across all of them, produces per-change proposals validated against a schema before touching disk.

🛡️

Two-layer redaction before anything leaves the machine

Every evidence excerpt runs through secret-token redaction (17 vendor shapes) and PII redaction (email, phone, address), then is truncated to ≤400 chars — redaction always applied before truncation so a boundary can't split a redaction marker.

📄

A digest you review, not a change you discover

/dream-digest renders the day's proposals grouped by project and kind, each with its evidence excerpts, prevalence count, and confidence. A durable canary banner flags schema drift or reduce failures until acknowledged.

Why it doesn't hallucinate memories

The safeguards

A memory system that grows itself is a poisoning surface — a wrong or malicious “learning” that gets injected into every future session. These are the layers that keep that from happening.

🙋

Human gate — nothing model-proposed is silent

Every dreaming proposal starts pending and stays there until you run /dream-apply and accept it. That is the only path from a mined proposal into the store.

🔗

Origin binding — evidence must be real

A proposal's cited sessions must resolve to actual transcript files on disk. The learning's writer is derived from that transcript's own recorded cwd — never from a caller-supplied env var — so a proposal can't forge a more-trusted origin than it has.

🧴

Injection sanitizer + quarantine

Untrusted transcript text is neutralized on write (role prefixes, “ignore previous instructions”, prompt tags). Independently, every read re-validates each entry and drops — quarantines — anything carrying unneutralized injection-shaped content. The analyzer's own prompts open by declaring excerpts are data, never instructions.

📉

Confidence decay & staleness

Every entry carries a 1–10 confidence that decays over time (≈90-day half-life) and is excluded once it falls below threshold. Reuse strengthens it; a contradict cuts it hard. Old memory doesn't silently masquerade as current truth.

🚫

Optimistic auto-integration is OFF by default — and bounded when on

The one optional automated write path, optimistic_integration (default false), never blanket-applies. Each op-kind gets a posture: verify integrates immediately (purely additive, reversible), while add / supersede and the eviction-shaped contradict / deprecate are written but held behind a 24-hour dwell window — excluded from every read path until it elapses, so a bad row can't reach a live session first. Per-slug caps bound how many land in one night, a batch-anomaly check watches eviction concentration, and a self-healing circuit breaker trips on repeated anomalies. Any _global change stays fully human-gated.

✅

An eval gate that fails closed

Before optimistic integration may act at all, dream-eval.sh --gate runs a with/without-memory A/B regression suite. Missing or red ⇒ no integration that run. Today the gate stays deliberately closed: the harness hasn't yet shown auto-integration beats human review, so /dream-apply remains the real write path.

Where your memory lives

Local by default

The read path is entirely on-machine. Opting into anything that leaves it is deliberate and explicit.

💾

Learnings never leave the machine

~/.claude/learnings/ is a local git repo with no remote by default. Cross-machine sync is opt-in — add your own private remote and ccgm-learnings-sync push. Never point it at a public repo.

🔕

Telemetry records counts, not content

Injection telemetry logs memory IDs, counts, and a token estimate — never the memory text. It's per-machine, lives outside the synced store, and is best-effort: any failure is swallowed and never alters the injected block.
